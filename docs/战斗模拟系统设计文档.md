# 战斗模拟系统设计文档

## 1. 文档目的

本文档定义 `packages/sim` 的核心设计。战斗模拟系统负责自动战斗的全部规则计算，包括移动、碰撞、伤害、状态、子弹、召唤、词条触发和胜负结算。

渲染层和 UI 层只能消费战斗快照与事件，不能直接修改战斗世界。

## 2. 核心原则

- 固定步长模拟。
- 可传入随机种子。
- 模拟结果可复现。
- 不依赖 React、PixiJS、DOM、Canvas 或真实系统时间。
- 战斗逻辑与视觉表现分离。
- 词条通过数据和事件钩子接入，避免散落特判。

## 3. 模拟入口

### createBattle

根据 MatchConfig 初始化战斗。

职责：

- 校验 MatchConfig。
- 加载双方 BuildConfig。
- 编译双方词条。
- 初始化 RNG。
- 初始化竞技场。
- 创建蓝方主球和红方主球。
- 应用基础属性和词条静态修正。

### stepBattle

推进一帧固定步长。

输入：

- 当前 BattleWorldState。
- 固定 dt，MVP 推荐 `1 / 60`。

输出：

- 更新后的 BattleWorldState。
- 本 tick 产生的 BattleEvent。

### getSnapshot

生成给渲染层使用的只读快照。

要求：

- 不暴露内部可变引用。
- 包含小球、子弹、炮台、事件、结果。
- 可按渲染需要裁剪字段。

## 4. Tick 执行顺序

MVP 推荐每个 tick 按以下顺序执行：

```txt
1. 清空上一 tick 临时事件
2. 如果已有 BattleResult，停止后续模拟
3. 更新时间 tick/time
4. 更新全局计时器
5. 执行 onTick 词条行为
6. 更新状态效果
7. 更新自动发射子弹
8. 更新召唤生成逻辑
9. 更新小球移动意图
10. 移动小球
11. 处理墙体反弹
12. 移动子弹
13. 处理子弹墙体反弹/消失
14. 处理小球之间碰撞
15. 处理子弹命中
16. 处理炮台攻击和生命周期
17. 处理死亡、复活、死亡分裂
18. 清理死亡实体和过期实体
19. 判断胜负
20. 生成 WorldSnapshot 所需事件
```

说明：

- 死亡处理放在伤害结算后统一进行，避免同一 tick 内状态混乱。
- 复活和死亡分裂属于死亡处理阶段。
- 渲染层不参与任何步骤。

## 5. 随机数

### RNG 要求

- 使用可 seed 的伪随机数。
- 所有随机行为必须从 BattleWorldState 内部 RNG 读取。
- 不允许使用 `Math.random()`。

### MVP 随机场景

- 初始移动方向。
- 轻微追敌扰动。
- 若后续词条需要随机弹道或随机目标，也必须使用同一个 RNG。

## 6. 编译构筑

### Build Compile

BuildConfig 进入战斗前需要编译为 RuntimeBuild。

编译步骤：

```txt
1. 校验 4 个 TraitId
2. 加载 TraitDefinition
3. 检查重复规则
4. 汇总静态属性修正
5. 汇总 behaviorKeys
6. 生成运行时行为集合
```

### 属性修正顺序

推荐顺序：

```txt
基础属性
-> 固定加法 add
-> 百分比加算 percentAdd
-> 乘法 multiplier
-> 上限/下限 clamp
```

MVP 中应尽量少用 multiplier。

## 7. 移动系统

### 基础规则

- 小球自动移动。
- 小球碰到墙体后反弹。
- 小球带轻微追敌倾向。
- 默认不做复杂寻路。

### 追敌倾向

每个 tick 可将当前速度方向向敌方主目标方向轻微插值。

推荐概念：

```txt
newDirection = lerp(currentDirection, targetDirection, chaseStrength * dt)
```

MVP 默认 chaseStrength 对应 30%-50% 的追敌倾向，具体实现可用可调常量。

### 墙体反弹

小球超出竞技场边界时：

- 将位置夹回合法区域。
- 反转对应速度分量。
- 触发 `onWallBounce`。
- 产生 wall bounce 事件供视觉反馈使用。

## 8. 碰撞系统

### 小球碰撞检测

两个敌对小球满足以下条件时视为碰撞：

```txt
distance <= radiusA + radiusB
```

### 碰撞冷却

同一对目标之间存在碰撞冷却。

默认：

```txt
collisionCooldown = 0.45 秒
```

冷却未结束时，不再次造成碰撞伤害，但仍可执行位置分离，避免实体重叠。

### 碰撞结算

碰撞发生时：

```txt
1. 分离重叠小球
2. 计算双方碰撞伤害
3. 双方互相造成伤害
4. 应用击退
5. 触发 onCollision
6. 记录碰撞冷却
```

### 击退

击退方向沿两球中心连线。

击退强度来自：

- 攻击方 knockback。
- 防守方可后续加入重量/抗击退，MVP 暂不做。
- 重力击退词条修正。

## 9. 伤害系统

### DamageRequest

所有伤害都应先形成 DamageRequest，再进入统一结算。

字段建议：

- sourceId
- targetId
- baseAmount
- tags
- position

### 伤害结算顺序

```txt
1. 创建 DamageRequest
2. 执行 onBeforeDamage
3. 应用脆弱等受伤倍率
4. 应用防御/减伤
5. 应用护盾
6. 扣除生命
7. 生成 DamageEvent
8. 执行 onAfterDamage
9. 标记可能死亡实体
```

### 标签

MVP 伤害标签：

- collision
- projectile
- dot
- explosion
- reflect

标签用于：

- 防止反伤连锁。
- 判断吸血是否触发。
- 判断状态是否附加。
- 统计伤害来源。

## 10. 治疗与吸血

### HealRequest

治疗统一进入 HealRequest。

字段建议：

- sourceId
- targetId
- amount
- tags

### 吸血碰撞

规则：

- 只由碰撞实际伤害触发。
- 回复实际伤害的 30%。
- 每秒最多回复 6 点生命。
- 不由反伤、DOT、爆炸触发。

### 生命上限

治疗不能超过当前最大生命。

## 11. 状态系统

### 状态更新顺序

每 tick：

```txt
1. 更新状态 elapsed
2. 处理 tickTimer
3. 执行状态周期效果
4. 移除过期状态
```

### MVP 状态

燃烧：

- 每秒 3 点伤害。
- 持续 2.5 秒。
- 刷新持续时间，不叠层。

中毒：

- 每秒 1.5 点伤害。
- 持续 5 秒。
- 刷新持续时间，不叠层。

减速：

- 移动速度 -30%。
- 持续 2 秒。
- 刷新持续时间，不叠层。

脆弱：

- 受到伤害 +20%。
- 持续 2.5 秒。
- 刷新持续时间，不叠层。

护盾：

- 每 7 秒获得 1 层。
- 抵挡 15 点伤害。
- 最多 1 层。

## 12. 弹道系统

### 启用条件

基础小球默认无远程攻击。

装备任意弹道类词条后，启用一套弱基础远程攻击。

弱基础远程攻击：

- 子弹伤害：4
- 发射间隔：1.6 秒
- 子弹速度：320
- 子弹半径：6
- 子弹存活：2.2 秒

### 发射逻辑

每个拥有远程攻击的小球维护 projectileCooldown。

当 cooldown <= 0：

```txt
1. 根据目标方向生成子弹
2. 应用霰弹/追踪/弹射/穿透/分裂等配置
3. 重置发射冷却
4. 生成 projectile fired 事件
```

### 子弹命中

子弹命中敌方小球时：

```txt
1. 造成 projectile 伤害
2. 附加可触发的状态
3. 处理穿透次数
4. 处理分裂
5. 判断是否销毁
```

### 分裂子弹

规则：

- 原子弹命中或消失时分裂为 2 枚小子弹。
- 小子弹继承 45% 伤害。
- 小子弹存活 1 秒。
- 小子弹不再继续分裂。

## 13. 召唤系统

### 克隆分身

规则：

- 每 7 秒生成 1 个分身。
- 分身生命 25。
- 半径 16。
- 速度为本体 90%。
- 碰撞伤害 3。
- 最多 4 个分身同时存在。

### 死亡分裂

规则：

- 构筑编译时主球最大生命 -50%。
- 主球第一次死亡时触发。
- 生成 2 个分裂体。
- 分裂体全部死亡才判负。
- 每局只触发一次。

### 自动炮台

规则：

- 每 8 秒生成 1 个炮台。
- 炮台生命 18。
- 持续 10 秒。
- 不移动。
- 每 1.8 秒发射 1 枚伤害 3 的子弹。
- 最多 2 个炮台同时存在。

## 14. 死亡与胜负

### 死亡处理

实体生命 <= 0 时标记死亡，统一进入死亡处理阶段。

处理顺序：

```txt
1. 触发 onDeath
2. 判断复活一次
3. 判断死亡分裂
4. 判断分身爆炸
5. 若无续战效果，确认死亡
```

### 胜负判断

默认：

- 主球死亡即判负。
- 如果死亡分裂已触发，则该方所有分裂体死亡后判负。
- 召唤物和炮台死亡不直接判负。

双 KO：

- 若双方同 tick 均达到判负条件，判定为 draw。
- 后续可加入剩余生命、伤害等裁决规则，MVP 暂不需要。

### 防卡死超时

MVP 可加入调试用超时，例如 180 秒。超时可判定为 draw，并记录 reason 为 timeout。

## 15. 词条事件钩子

MVP 推荐支持以下钩子：

```txt
onBuildCompile
onBattleStart
onTick
onWallBounce
onCollision
onBeforeDamage
onAfterDamage
onProjectileFire
onProjectileHit
onDeath
onKill
```

各词条映射：

- 生命强化：onBuildCompile
- 高速移动：onBuildCompile
- 巨型球体：onBuildCompile
- 小型灵巧：onBuildCompile
- 碰撞强化：onBuildCompile
- 坚硬外壳：onBuildCompile/onBeforeDamage
- 吸血碰撞：onAfterDamage
- 尖刺反伤：onAfterDamage
- 重力击退：onBuildCompile/onCollision
- 碰撞爆炸：onCollision
- 撞墙蓄力：onWallBounce/onCollision
- 弹道类：onBuildCompile/onProjectileFire/onProjectileHit
- 克隆分身：onTick
- 死亡分裂：onBuildCompile/onDeath
- 分身爆炸：onDeath
- 自动炮台：onTick
- 状态类：onCollision/onProjectileHit/onTick
- 低血狂暴：onAfterDamage/onTick
- 击杀成长：onKill
- 时间成长：onTick
- 复活一次：onBuildCompile/onDeath

## 16. 事件与快照

模拟每 tick 生成 BattleEvent。

事件用途：

- 视觉反馈。
- HUD 更新。
- 结算统计。
- 调试面板。
- 后续录像摘要。

渲染层只读取 WorldSnapshot 和 BattleEvent，不反向修改模拟状态。

## 17. 单元测试建议

P0 测试：

- 无词条战斗能结束。
- 相同 seed 可复现。
- 碰撞冷却有效。
- 击退方向正确。
- 吸血每秒上限有效。
- 反伤不触发连锁。
- 碰撞爆炸冷却有效。
- 分裂子弹不继续分裂。
- 克隆分身数量上限有效。
- 死亡分裂判负规则正确。
- 护盾抵挡伤害正确。
- 复活一次每局只触发一次。

P1 测试：

- 预设敌人构筑合法。
- 30 个词条定义合法。
- 批量模拟输出稳定。
