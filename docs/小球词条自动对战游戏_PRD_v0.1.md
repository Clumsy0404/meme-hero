# 小球词条自动对战游戏 PRD v0.1

## 1. Executive Summary

### Problem Statement

固定角色式小球对战游戏的内容扩展依赖持续设计新角色，长期会增加设计、数值和平衡成本。我们希望将角色能力拆成可组合词条，让玩家通过构筑创造不同流派。

### Proposed Solution

设计一款以“基础小球 + 3 个词条构筑”为核心的自动对战游戏。所有小球默认具备自动移动与碰撞伤害，词条用于改变基础数值、攻击方式、技能、状态、召唤物和规则效果。

### Success Criteria

- MVP 支持玩家为小球自由选择固定 3 个词条。
- MVP 支持完整自动战斗流程：配置、开战、自动对战、胜负结算。
- 没有词条的小球也能完成一局基础碰撞战斗。
- MVP 至少能验证 5 类流派雏形：碰撞流、生存流、弹道流、召唤流、状态流。
- 单局战斗建议控制在 30-90 秒，具体数值待实测确认。

## 2. User Experience & Functionality

### User Personas

- 构筑型玩家：希望通过自由搭配词条研究强力或有趣组合。
- 自动对战玩家：希望观看构筑结果，通过战斗反馈判断策略优劣。
- 挑战型玩家：后续希望挑战其他玩家上传的擂台构筑。
- 内容创作者：后续可能使用热梗词条和极简战斗画面制作对战内容。

### User Stories

- As a player, I want to choose 3 traits for my ball so that I can build a distinct combat style.
- As a player, I want battles to run automatically so that build decisions matter more than real-time operation.
- As a player, I want traits to visibly affect combat so that I can understand why a build wins or loses.
- As a challenger, I want to fight against another player's saved build so that I can test my own build asynchronously.
- As a designer, I want traits to be modular so that new mechanics and meme-inspired traits can be added without redesigning fixed characters.

### Acceptance Criteria

- 玩家可以在战前为小球装备固定 3 个词条。
- MVP 阶段词条从词条库中自由选择。
- MVP 第一批词条数量约 30 个。
- 词条命名采用“双名称制”：热梗展示名 + 功能副标题，展示名允许后续修改。
- 词条使用“主类型 + 多标签”结构。
- 词条分类型，但不强制每类只能选一个，也不强制每类必须选择。
- 部分词条可重复，部分词条不可重复，重复规则由词条自身配置决定。
- MVP 暂不做词条稀有度。
- 词条可以是纯正面效果，也可以有正负面代价。
- 所有小球默认自动移动。
- 所有小球默认通过碰撞进行近战伤害结算。
- 敌对小球碰撞时，双方互相造成碰撞伤害，并产生反弹或击退。
- 主小球死亡即失败，召唤物死亡不直接判负。
- 对战界面需要展示双方生命值或核心数值、装备词条、胜负结果。
- MVP 支持玩家手动配置双方，也支持挑战预设敌人。
- MVP 预设敌人数量为 6 个，覆盖碰撞、吸血生存、弹道、召唤、状态消耗、后期成长等流派。

### Non-Goals

- MVP 不做实时好友联机。
- MVP 不做完整擂台服务器。
- MVP 不做账号系统、排行榜、复杂经济系统。
- MVP 不做长线养成与词条稀有度。
- MVP 不做复杂角色剧情。
- MVP 不以战斗中手动操作为核心。
- MVP 不优先投入大量美术资产，先采用极简圆球风格。

## 3. AI System Requirements

### Tool Requirements

MVP 不强依赖 AI 系统。后续可选 AI 能力包括：

- 根据网络热梗生成词条名称、描述和效果草案。
- 自动生成对战标题或短视频文案。
- 批量模拟对战后生成平衡性分析报告。

### Evaluation Strategy

如后续接入 AI，需要验证：

- 生成词条是否符合数据结构。
- 生成词条是否存在数值越界或不可执行效果。
- 生成文案是否安全、可读、符合平台内容规范。
- AI 生成内容必须经过人工确认后进入正式词条库。

## 4. Technical Specifications

### Architecture Overview

技术栈已确认采用 TypeScript Web 路线。MVP 以纯前端单机 Demo 为目标，战斗模拟核心与渲染/UI 解耦，后续可复用于擂台战校验、录像回放、批量平衡测试和好友对战结果复现。推荐先围绕以下领域设计需求与数据结构：

- 基础小球：承载生命、大小、速度、碰撞伤害等基础字段。
- 词条系统：承载属性修改、触发条件、效果执行、重复规则和代价。
- 战斗世界：管理自动移动、碰撞、实体生命周期、胜负结算。
- 弹道实体：管理子弹、激光、导弹、轨道物等由词条产生的攻击对象。
- 状态系统：管理燃烧、中毒、减速、护盾、脆弱等状态效果。
- 召唤系统：管理分身、召唤球、炮台、地雷等额外实体。
- 配置/存档系统：用于保存玩家构筑，后续支持擂台战上传与挑战。

### Core Combat Model

基础小球字段 v0.1：

- 生命值
- 半径/大小
- 移动速度
- 碰撞伤害
- 碰撞冷却
- 击退力度
- 防御/减伤
- 生命回复

基础小球默认数值 v0.1 暂定测试值：

- 最大生命：100
- 半径：24
- 移动速度：180
- 碰撞伤害：8
- 碰撞冷却：0.45 秒
- 击退力度：220
- 防御/减伤：0
- 生命回复：0

基础数值设计目标：

- 没有词条的小球也能完成一局基础对战。
- 无词条对局建议在 30-60 秒内分出胜负。
- 具体数值以后续实机测试和战斗时长统计为准。

默认战斗规则：

- 小球在场地内自动移动。
- MVP 使用矩形竞技场。
- 小球碰到场地边界后反弹。
- 小球移动方向带轻微追敌倾向，默认建议 30%-50%，具体数值待实测。
- 敌对小球发生碰撞时，双方互相造成碰撞伤害。
- 碰撞后双方产生反弹或击退。
- 同一组目标之间存在短暂碰撞冷却，避免连续帧重复扣血。
- 没有词条时，小球仍可通过移动与碰撞完成战斗。

### Trait Impact Domains

词条可影响 6 个核心机制域：

- 生存机制：生命、治疗、吸血、护盾、减伤、复活、死亡触发。
- 运动机制：速度、大小、转向、冲刺、追踪、逃离、撞墙反弹。
- 伤害机制：碰撞伤害、攻击倍率、暴击、反伤、持续伤害、斩杀。
- 弹道机制：子弹生成、数量、速度、追踪、弹射、穿透、分裂、爆炸。
- 召唤机制：克隆、分身、炮台、地雷、召唤物继承属性、数量上限。
- 状态与规则机制：中毒、燃烧、减速、眩晕、脆弱、成长叠层、低血爆发、场地效果等。

### Trait Numeric Principles

MVP 词条数值采用“百分比 + 固定值 + 限制规则”的混合口径：

- 改变小球自身基础属性时，优先使用百分比。
- 生成独立效果时，优先使用固定值。
- 高强度规则效果通过冷却、次数、上限或负面代价控制。
- 百分比加成默认采用加算，避免乘算导致数值膨胀。
- 关键机制需要设置软上限或硬上限，例如吸血、减伤、召唤物数量、控制效果。

适合使用百分比的字段：

- 最大生命
- 移动速度
- 碰撞伤害
- 受到伤害倍率
- 子弹伤害倍率
- 冷却时间倍率
- 治疗/吸血倍率

适合使用固定值的字段：

- 子弹基础伤害
- 燃烧/中毒每秒伤害
- 护盾值
- 召唤物生命
- 召唤物碰撞伤害
- 撞墙蓄力每层附加伤害

适合使用限制规则的机制：

- 复活一次
- 死亡分裂
- 克隆分身
- 吸血碰撞
- 碰撞爆炸
- 控制状态
- 成长叠层

### Balance Anchor Model

MVP v0.1 采用以下平衡锚点指导第一批词条数值。该模型用于确定初始数值，不作为最终平衡公式。

强度目标：

- 无词条小球强度：1.0
- 4 词条普通构筑强度：2.0-2.5
- 4 词条强协同构筑强度：约 3.0
- 明显失控构筑强度：大于 4.0，需要削弱或增加限制。

战斗时长目标：

- 无词条 vs 无词条：30-60 秒。
- 4 词条普通构筑 vs 无词条：15-30 秒内明显获胜。
- 4 词条 vs 4 词条均衡构筑：30-90 秒。
- 克制构筑 vs 被克制构筑：20-60 秒。

词条强度原则：

- 单个词条应明显有效，但不能单独决定胜负。
- 普通纯数值词条提供约 20%-35% 的单项收益。
- 带副作用的机制词条可以拥有更高等效收益。
- 复活、分裂、吸血、召唤、控制等强机制必须通过代价、冷却、次数或上限约束。
- 第一版数值优先保守，后续通过自动对战统计调整。

### MVP Trait Set

MVP 第一批词条约 30 个，按以下配比分布：

- 属性类：6 个
- 碰撞类：5 个
- 弹道类：6 个
- 召唤类：4 个
- 状态类：5 个
- 规则类：4 个

属性类：

- 生命强化：最大生命 +30%，可重复。
- 高速移动：移动速度 +20%，可重复。
- 巨型球体：半径 +25%，最大生命 +20%，碰撞伤害 +15%，移动速度 -10%，可重复但需要体型上限。
- 小型灵巧：半径 -20%，移动速度 +20%，最大生命 -15%，可重复但需要体型下限。
- 碰撞强化：碰撞伤害 +25%，可重复。
- 坚硬外壳：受到伤害 -12%，移动速度 -5%，可重复但最终减伤上限建议 60%。

属性类计算规则：

- 百分比默认加算。
- 内部允许小数计算。
- UI 显示时可四舍五入。

碰撞类：

- 吸血碰撞：造成碰撞伤害时，回复实际伤害的 30%，每秒最多回复 6 点生命，不可重复。
- 尖刺反伤：受到碰撞伤害时，向伤害来源反弹 35% 实际伤害；反伤不触发吸血、反伤、状态命中效果，不可重复。
- 重力击退：碰撞击退力度 +60%，碰撞伤害 +10%，可重复但击退需要上限。
- 碰撞爆炸：发生碰撞时触发半径 60 的爆炸，造成 6 点范围伤害，冷却 2.5 秒；爆炸不再次触发碰撞爆炸，不可重复。
- 撞墙蓄力：每次撞墙获得 1 层蓄力，最多 5 层；下次碰撞每层额外造成 3 点伤害并清空；每 0.3 秒最多获得 1 层，不可重复。

弹道类：

- 远程核心：子弹伤害 +35%，发射间隔 -20%，子弹速度 +15%，可重复但发射间隔需要下限。
- 霰弹发射：每次发射 3 枚扇形子弹，每颗子弹伤害 *0.7，子弹散角约 25°，不可重复。
- 弹射子弹：子弹撞墙后可反弹 2 次，子弹伤害 -10%，不可重复。
- 追踪子弹：子弹轻微转向最近敌方目标，子弹伤害 -15%，不可重复。
- 穿透子弹：子弹可额外穿透 1 个目标，子弹伤害 -10%，不可重复。
- 分裂子弹：子弹命中或消失时分裂为 2 枚小子弹；小子弹继承 45% 伤害，存活 1.0 秒，且不再继续分裂，不可重复。

弹道类基础规则：

- 基础小球默认无远程攻击。
- 装备任意弹道类词条后，启用一套弱基础远程攻击。
- 装备任意弹道类词条后，小球本体碰撞伤害归零；弹道流主要依靠子弹造成伤害。
- 多个弹道类词条共同修改同一套远程攻击。
- 远程核心不负责开启远程攻击，而是强化远程攻击基础数值。

弱基础远程攻击 v0.1：

- 子弹伤害：2
- 发射间隔：1.6 秒
- 子弹速度：280
- 子弹半径：6
- 子弹存活：2.2 秒

召唤类：

- 克隆分身：每 7 秒生成 1 个分身；分身生命 25，半径 16，速度为本体 90%，碰撞伤害 3；最多 4 个分身同时存在，分身持续到死亡，不可重复。
- 死亡分裂：主球最大生命 -50%；主球第一次死亡时分裂为 2 个分裂体继续战斗；每个分裂体生命 25，半径 18，速度为本体 110%，碰撞伤害 4；每局只能触发 1 次，分裂体全部死亡才判负，不可重复。
- 分身爆炸：己方召唤物死亡时爆炸，爆炸半径 55，爆炸伤害 5；同一召唤物只爆炸 1 次，爆炸不触发召唤物死亡连锁，不可重复。
- 自动炮台：每 8 秒生成 1 个炮台；炮台生命 18，持续 10 秒，不移动；每 1.8 秒发射 1 枚子弹，伤害 1，速度 280；最多 2 个炮台同时存在，不可重复。

状态类：

- 燃烧：命中后附加燃烧，每秒造成 3 点伤害，持续 2.5 秒；刷新持续时间，不叠层，不可重复。
- 中毒：命中后附加中毒，每秒造成 1.5 点伤害，持续 5 秒；刷新持续时间，不叠层，不可重复。
- 减速：命中后使目标移动速度 -30%，持续 2 秒；刷新持续时间，不叠层，不可重复。
- 脆弱：命中后使目标受到伤害 +20%，持续 2.5 秒；刷新持续时间，不叠层，不可重复。
- 护盾：每 7 秒获得 1 层护盾，护盾值抵挡 15 点伤害；最多同时存在 1 层护盾，不可重复。

状态类基础规则：

- 燃烧、中毒、减速、脆弱默认可由碰撞和子弹命中触发。
- 护盾默认周期性自动触发。
- 燃烧、中毒、减速、脆弱重复命中时刷新持续时间，不无限叠层。

规则类：

- 低血狂暴：生命首次低于 30% 时触发；移动速度 +30%，碰撞伤害 +30%，子弹发射间隔 -20%，持续 6 秒；每局触发 1 次，不可重复。
- 击杀成长：击杀敌方召唤物或主球时触发；最大生命 +5，碰撞伤害 +1；最多触发 6 次，主要用于召唤物对局，不可重复。
- 时间成长：战斗每经过 10 秒触发 1 次；碰撞伤害 +8%，移动速度 +5%；最多 6 层，不可重复。
- 复活一次：最大生命 -25%；第一次死亡时原地复活，恢复 35 点生命，并获得 1 秒无敌；每局触发 1 次，不可重复。

复活一次与死亡分裂的区别：

- 复活一次：死亡后仍是一个主球。
- 死亡分裂：死亡后变成多个较弱分裂体。

### Attack & Skill Model

- 默认攻击方式为近战碰撞。
- 远程子弹、轨道物、激光、护盾、导弹、灼烧、减速、追踪等能力由词条提供。
- 主动技能在本游戏中优先理解为“自动战斗中自动释放的冷却技能”，不是玩家手动按键释放。
- 被动技能为持续生效或事件触发效果。

### Game Modes

MVP：

- 单机可玩 Demo。
- 玩家自由选择词条并进行自动对战。
- 自由对战：玩家可以手动配置蓝方和红方各 3 个词条。
- 挑战预设敌人：玩家配置自己的 3 个词条，然后挑战 6 个预设敌人之一。

MVP 预设敌人方向：

- 碰撞流敌人：高生命、高碰撞、高击退。
- 吸血生存流敌人：吸血、防御、护盾、生命强化。
- 弹道流敌人：远程强化、弹射、追踪、霰弹/穿透。
- 召唤流敌人：克隆、分身爆炸、自动炮台、生存词条。
- 状态消耗流敌人：燃烧、中毒、减速、脆弱。
- 后期成长流敌人：时间成长、复活、护盾、防御。

MVP 基础界面流程：

- 配置界面
- 开始战斗
- 结算界面
- 返回配置

MVP 结算必做信息：

- 胜者
- 战斗时长
- 双方剩余生命
- 双方装备词条

后续模式：

- 擂台战/异步挑战：玩家上传构筑存档，其他玩家挑战该构筑。
- 好友对战/实时联机：两个玩家各自配置小球后实时对战，后续再评估实现复杂度。

### Integration Points

- 技术栈：TypeScript Web 技术栈，推荐 Vite + React + PixiJS + 纯 TypeScript 战斗模拟核心。
- 是否基于现有 Pygame 项目改造：否。Pygame 项目可作为玩法参考，但本项目主工程建议从 Web 技术栈重新开发。
- 构筑存档格式：建议使用 JSON 或等价结构，至少包含版本号、基础模型、皮肤、3 个词条 ID。
- 联机服务与账号系统：MVP 暂不实现。

### Security & Privacy

- MVP 为本地单机 Demo，暂无用户隐私数据。
- 后续如支持上传构筑，需要考虑配置校验、非法词条过滤、版本兼容和滥用处理。
- 后续如支持账号、排行榜或联机，需要补充账号安全、日志、隐私和反作弊策略。

## 5. Risks & Roadmap

### Phased Rollout

MVP v0.1：

- 极简圆球美术。
- 基础小球自动移动与碰撞伤害。

### Technical Risks

- 词条组合可能数值爆炸，需要吸血上限、召唤上限、控制递减、冷却限制。
- 分身、子弹、轨道物过多可能导致性能下降，需要实体数量上限和清理规则。
- 词条效果如果视觉反馈不足，玩家难以理解构筑胜负原因。
- 过多规则改变类词条会增加平衡和调试成本，MVP 应优先控制数量。
- 后续实时联机复杂度较高，需要提前保证战斗可复现、构筑可序列化、随机数可控。

## Confirmed Decisions

- 产品方向：玩家自己选词条、配构筑、打对战或关卡。
- 战斗方式：先做完全自动战斗。
- 词条获取：MVP 先自由选择。
- 装备数量：每个小球固定 3 个词条。
- 词条数量：MVP 第一批约 30 个。
- 词条命名：双名称制，展示名后续可改。
- 词条结构：主类型 + 多标签。
- 词条类型：区分类型，但不限制搭配比例。
- 词条重复：部分可重复，部分不可重复。
- 词条稀有度：MVP 暂不做。
- 词条代价：允许纯正面，也允许正负面权衡。
- 战斗规模：MVP 先 1v1，后续扩展组队。
- 美术风格：MVP 极简圆球，后续支持皮肤/头像替换。
- 技术栈：采用 TypeScript Web 技术栈，MVP 为纯前端单机 Demo，战斗模拟核心与渲染/UI 解耦。
- 默认攻击：所有小球默认近战碰撞，碰撞时双方互相造成伤害。
- 远程例外：装备任意弹道类词条后，本体碰撞伤害归零，但仍保留碰撞位置分离和击退表现。
- 对战配置：MVP 支持手动配置双方和挑战 6 个预设敌人。
- 场地移动：矩形竞技场，自动反弹移动，轻微追敌倾向。
- 胜负结算：主球死亡判负，结算显示胜者、时长、剩余生命、双方词条。
- 基础数值：最大生命 100、半径 24、速度 180、碰撞伤害 8、碰撞冷却 0.45 秒、击退 220、防御 0、生命回复 0，均为 v0.1 暂定测试值。
