# 数据模型设计文档

## 1. 文档目的

本文档定义 MVP 阶段的核心数据模型，包括词条、构筑、对战配置、战斗实体、状态、事件和快照。具体代码实现时应以 TypeScript 类型为准，但整体结构应遵循本文档。

## 2. 设计原则

- 机制 ID 与展示名分离。
- 构筑配置与对战配置分离。
- 静态内容与运行时状态分离。
- 模拟层数据不依赖 React、PixiJS、DOM 或浏览器 API。
- 所有可复现战斗都应包含版本号与随机种子。

## 3. 静态内容模型

### TraitDefinition

词条定义。存放在 `packages/content`。

```ts
type TraitDefinition = {
  id: TraitId;
  name: string;
  subtitle: string;
  mainType: TraitType;
  tags: TraitTag[];
  repeatRule: RepeatRule;
  description: string;
  numeric: TraitNumericConfig;
  behaviorKeys: BehaviorKey[];
};
```

字段说明：

- `id`：稳定机制 ID，不随展示名变化。
- `name`：热梗展示名，可后续修改。
- `subtitle`：功能副标题，例如“吸血碰撞”。
- `mainType`：主类型，用于 UI 分类。
- `tags`：多标签，用于机制识别、筛选和平衡统计。
- `repeatRule`：重复选择规则。
- `description`：面向玩家的描述。
- `numeric`：该词条涉及的数值配置。
- `behaviorKeys`：该词条启用的运行时行为。

### TraitType

```ts
type TraitType =
  | "attribute"
  | "collision"
  | "projectile"
  | "summon"
  | "status"
  | "rule";
```

### TraitTag

标签可扩展，MVP 建议包含：

```ts
type TraitTag =
  | "hp"
  | "speed"
  | "size"
  | "defense"
  | "collision"
  | "damage"
  | "lifesteal"
  | "reflect"
  | "knockback"
  | "explosion"
  | "wall"
  | "projectile"
  | "scatter"
  | "bounce"
  | "homing"
  | "pierce"
  | "split"
  | "clone"
  | "turret"
  | "death"
  | "burn"
  | "poison"
  | "slow"
  | "vulnerable"
  | "shield"
  | "growth"
  | "revive";
```

### RepeatRule

```ts
type RepeatRule =
  | { kind: "unique" }
  | { kind: "stackable"; maxStacks?: number };
```

MVP 规则：

- 基础数值类词条可以重复。
- 大多数机制类词条不可重复。
- 可重复词条默认百分比加算。

### TraitNumericConfig

用于记录词条数值。不要把所有字段强行塞到同一个大对象里，推荐按能力分组。

```ts
type TraitNumericConfig = {
  statModifiers?: StatModifier[];
  collision?: CollisionTraitConfig;
  projectile?: ProjectileTraitConfig;
  summon?: SummonTraitConfig;
  status?: StatusTraitConfig;
  rule?: RuleTraitConfig;
};
```

### StatModifier

```ts
type StatModifier = {
  stat: StatKey;
  op: "add" | "percentAdd" | "multiplier";
  value: number;
};
```

MVP 建议：

- 属性类词条主要使用 `percentAdd`。
- 固定伤害、护盾、DOT、召唤物生命等使用具体配置字段。
- `multiplier` 谨慎使用，避免数值膨胀。

### StatKey

```ts
type StatKey =
  | "maxHp"
  | "radius"
  | "moveSpeed"
  | "collisionDamage"
  | "collisionCooldown"
  | "knockback"
  | "damageReduction"
  | "hpRegen";
```

## 4. 构筑与对战配置

### BuildConfig

构筑配置描述一个小球。

```ts
type BuildConfig = {
  version: string;
  name: string;
  skin: string;
  baseModel: string;
  traits: TraitId[];
};
```

MVP 校验规则：

- `traits.length === 4`
- 所有 TraitId 必须存在。
- 重复选择必须符合 RepeatRule。
- `version` 必须存在。

### PresetBuild

预设敌人配置。

```ts
type PresetBuild = {
  id: string;
  name: string;
  description: string;
  build: BuildConfig;
  tags: string[];
};
```

MVP 预设：

- 碰撞流
- 吸血生存流
- 弹道流
- 召唤流
- 状态消耗流
- 后期成长流

### MatchConfig

对战配置描述一次战斗。

```ts
type MatchConfig = {
  version: string;
  seed: number;
  arenaId: string;
  blue: BuildConfig;
  red: BuildConfig;
};
```

说明：

- 擂台战上传 BuildConfig。
- 录像复现和服务端校验需要 MatchConfig。
- 相同 MatchConfig 在相同 sim 版本下应产生相同战斗结果。

## 6. 运行时实体模型

### EntityId

```ts
type EntityId = string;
```

实现时可以使用递增数字转字符串，保证同一 seed 下生成顺序稳定。

### Team

```ts
type Team = "blue" | "red";
```

### Vec2

```ts
type Vec2 = {
  x: number;
  y: number;
};
```

### BallState

```ts
type BallState = {
  id: EntityId;
  team: Team;
  role: BallRole;
  ownerId?: EntityId;
  alive: boolean;
  hp: number;
  stats: BallStats;
  position: Vec2;
  velocity: Vec2;
  collisionTimers: Record<EntityId, number>;
  statuses: StatusInstance[];
  runtime: BallRuntimeState;
};
```

### BallRole

```ts
type BallRole =
  | "main"
  | "clone"
  | "split";
```

说明：

- `main`：主球。
- `clone`：克隆分身，死亡不判负。
- `split`：死亡分裂后的分裂体，分裂体全部死亡才判负。

### BallRuntimeState

记录词条运行时变量。

```ts
type BallRuntimeState = {
  wallChargeStacks?: number;
  lifestealWindow?: RateLimitState;
  collisionExplosionCooldown?: number;
  cloneSpawnCooldown?: number;
  turretSpawnCooldown?: number;
  lowHpRageTriggered?: boolean;
  reviveUsed?: boolean;
  deathSplitUsed?: boolean;
  growthStacks?: number;
  timeGrowthStacks?: number;
  projectileCooldown?: number;
};
```

实现时可进一步拆成行为私有状态，但快照中只保留需要调试或复现的字段。

type ProjectileState = {

## 7. 状态模型

### StatusInstance

```ts
type StatusInstance = {
  id: StatusId;
  sourceId?: EntityId;
  duration: number;
  elapsed: number;
  tickTimer?: number;
  data?: Record<string, number | string | boolean>;
};
```

### StatusId

```ts
type StatusId =
  | "burn"
  | "poison"
  | "slow"
  | "vulnerable"
  | "shield"
  | "rage";
```

MVP 叠加规则：

- 燃烧、中毒、减速、脆弱：重复命中刷新持续时间，不叠层。
- 护盾：最多 1 层。
- 狂暴：每局触发一次，持续时间结束后移除。

MVP 可先使用固定矩形竞技场。

```ts

## 9. 事件模型

### BattleEvent

type BattleEvent =
  | DamageEvent

  | DeathEvent
  | SpawnEvent
  | StatusAppliedEvent
  | ExplosionEvent
  | ShieldEvent
  | TraitTriggeredEvent
  | MatchEndEvent;
```

### DamageEvent

```ts
type DamageEvent = {
  type: "damage";
  tick: number;
  sourceId?: EntityId;
  targetId: EntityId;
  amount: number;
  tags: DamageTag[];
  position: Vec2;
};
```

### DamageTag

```ts
type DamageTag =
  | "collision"
  | "projectile"
  | "dot"
  | "explosion"
  | "reflect";
```

事件用途：

- 驱动视觉反馈。
- 驱动结算统计。
- 驱动调试面板。
- 后续可用于录像摘要。

## 10. 结算模型

### BattleResult

```ts
type BattleResult = {
  winner: Team | "draw";
  reason: BattleEndReason;
  duration: number;
  blueRemainingHp: number;
  redRemainingHp: number;
};
```

### BattleEndReason

```ts
type BattleEndReason =
  | "main_ball_dead"
  | "split_balls_dead"
  | "double_ko"
  | "timeout";
```

MVP 默认：

- 主球死亡判负。
- 有死亡分裂时，分裂体全部死亡才判负。
- 双方同时死亡且无法判定先后时平局。
- 超时规则可后续加入，MVP 可先设调试用上限防卡死。

## 12. 校验规则

构筑校验：

- 版本号存在。
- 基础模型存在。
- 皮肤存在或回退默认皮肤。
- 词条数量等于 4。
- 所有词条 ID 存在。
- 重复规则合法。

对战校验：

- seed 存在。
- arenaId 存在。
- 蓝红双方构筑合法。
- 对战版本兼容当前 sim 版本。

词条校验：

- ID 唯一。
- name 和 subtitle 非空。
- mainType 合法。
- tags 非空。
- repeatRule 合法。
- behaviorKeys 可被 sim 识别。

## 13. 后续扩展预留

后续擂台战可能增加：

- 上传者 ID。
- 构筑公开状态。
- 构筑签名或校验 hash。
- 版本兼容范围。
- 胜率和挑战统计。

后续好友对战可能增加：

- 房间 ID。
- 玩家 ready 状态。
- 服务端生成 seed。
- 对战结果回传。

后续录像可能增加：

- MatchConfig。
- sim 版本。
- 关键事件列表。
- 最终 BattleResult。
