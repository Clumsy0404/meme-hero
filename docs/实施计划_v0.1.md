# 实施计划 v0.1

## 1. 目标

本文档定义 MVP 的实施顺序、阶段目标和验收标准。实施原则是先做可运行的最小战斗闭环，再逐步扩展词条、UI、渲染和测试工具。

## 2. 实施原则

- 先模拟，后表现。
- 先无词条战斗，后词条系统。
- 先固定数据，后编辑器和导入导出。
- 先单机确定性，后擂台战和好友对战。
- 每个阶段都要有可运行成果，不堆大分支。

## 3. 阶段划分

### Phase 0：工程初始化

目标：建立可开发、可测试的基础工程。

任务：

- 初始化 pnpm workspace。
- 创建 `apps/web`。
- 创建 `packages/sim`。
- 创建 `packages/content`。
- 创建 `packages/shared`。
- 配置 TypeScript。
- 配置 Vite + React。
- 配置 Vitest。
- 配置基础 lint/format 脚本，具体工具可在初始化时确认。

验收：

- 本地开发服务器可启动。
- 页面显示基础应用壳。
- `packages/sim` 可被 `apps/web` 引用。
- 测试命令可运行。

建议产出：

- 空白配置页。
- 空白战斗页。
- 一个 sim 单元测试样例。

### Phase 1：无词条战斗闭环

目标：不用任何词条，完成基础小球自动战斗。

任务：

- 实现 seeded RNG。
- 实现固定步长模拟循环。
- 实现矩形竞技场。
- 实现 Ball 实体。
- 实现基础属性：
  - 最大生命 100
  - 半径 24
  - 移动速度 180
  - 碰撞伤害 8
  - 碰撞冷却 0.45 秒
  - 击退力度 220
  - 防御 0
  - 生命回复 0
- 实现自动移动、墙体反弹、轻微追敌倾向。
- 实现碰撞检测、伤害、击退、死亡、胜负结算。
- 输出 WorldSnapshot。

验收：

- 无词条蓝球 vs 无词条红球可自动分出胜负。
- 相同 seed 结果可复现。
- 模拟层不依赖 React、PixiJS、DOM 或真实时间。

建议测试：

- 伤害结算。
- 碰撞冷却。
- 主球死亡判负。
- 相同 seed 可复现。

### Phase 2：基础渲染与战斗页

目标：能在浏览器中看见基础战斗。

任务：

- 引入 PixiJS 渲染层。
- 渲染竞技场、小球、生命数字。
- 渲染基础碰撞反馈。
- React 页面提供开始战斗、重新开始、返回配置。
- 战斗结束显示基础结算。

验收：

- 浏览器中可看到小球移动、碰撞、扣血、死亡。
- 战斗结束后出现胜者、战斗时长、剩余生命。
- 渲染层只消费模拟快照，不直接改模拟状态。

### Phase 3：构筑与词条数据

目标：建立词条库和构筑配置，但先只实现属性类。

任务：

- 定义 TraitDefinition。
- 定义 BuildConfig。
- 定义 MatchConfig。
- 实现词条库加载。
- 实现 30 个词条的静态定义。
- 实现构筑校验：
  - 固定 3 个词条。
  - 词条 ID 存在。
  - 重复规则正确。
- 实现属性类 6 个词条。

验收：

- 页面能展示 30 个词条。
- 玩家能为双方选择 3 个词条。
- 属性类词条能影响战斗。
- 不可重复词条不能重复选择。

建议测试：

- BuildConfig 校验。
- 词条重复规则。
- 属性加成加算。

### Phase 4：碰撞类词条

目标：强化默认碰撞玩法，形成近战构筑。

任务：

- 实现战斗事件钩子：
  - onCollision
  - onDamage
  - onWallBounce
- 实现吸血碰撞。
- 实现尖刺反伤。
- 实现重力击退。
- 实现碰撞爆炸。
- 实现撞墙蓄力。
- 补充碰撞类视觉反馈。

验收：

- 5 个碰撞类词条均可观察。
- 吸血有每秒上限。
- 反伤不连锁。
- 爆炸有冷却。
- 撞墙蓄力不能贴墙刷层。

### Phase 5：弹道系统

目标：实现远程攻击和弹道类词条。

任务：

- 实现 Projectile 实体。
- 装备任意弹道类词条后启用弱基础远程攻击。
- 装备任意弹道类词条后，本体碰撞伤害归零。
- 实现子弹移动、命中、存活时间、墙体反弹。
- 实现远程核心。
- 实现霰弹发射。
- 实现弹射子弹。
- 实现追踪子弹。
- 实现穿透子弹。
- 实现分裂子弹。
- 增加子弹渲染。

验收：

- 无弹道词条时不发射子弹。
- 有任意弹道词条时发射弱基础子弹。
- 多个弹道词条共同修改同一套远程攻击。
- 小子弹不继续分裂。

### Phase 6：召唤系统

目标：实现召唤物、分裂体和炮台。

任务：

- 扩展 Ball 支持主球、分身、分裂体。
- 实现 Turret 实体。
- 实现克隆分身。
- 实现死亡分裂。
- 实现分身爆炸。
- 实现自动炮台。
- 增加召唤物与炮台渲染。

验收：

- 克隆分身数量不超过 4。
- 死亡分裂每局只触发一次。
- 分裂体全部死亡才判负。
- 炮台最多同时存在 2 个。

### Phase 7：状态系统与规则类词条

目标：实现状态效果和反转/成长型规则。

任务：

- 实现 StatusEffect 模型。
- 实现燃烧、中毒、减速、脆弱、护盾。
- 实现低血狂暴。
- 实现击杀成长。
- 实现时间成长。
- 实现复活一次。
- 增加状态视觉反馈。

验收：

- 同类状态刷新持续时间，不无限叠层。
- 护盾最多 1 层。
- 低血狂暴每局一次。
- 击杀成长和时间成长有上限。
- 复活一次每局一次且有生命代价。

### Phase 8：完整配置界面与预设敌人

目标：把 Demo 做成完整可玩的 MVP 流程。

任务：

- 配置界面支持蓝方和红方构筑。
- 增加自由对战模式。
- 增加挑战预设敌人模式。
- 实现 6 个预设敌人。
- 战斗 HUD 展示双方词条、生命和时间。
- 结算界面展示胜者、时长、剩余生命、双方词条。

验收：

- 玩家可以完整完成配置 -> 战斗 -> 结算 -> 返回配置。
- 6 个预设敌人都可挑战。
- 自由对战可配置双方。

### Phase 9：本地保存与平衡工具

目标：提高测试效率，为后续擂台战做准备。

任务：

- 本地保存构筑。
- 本地读取构筑。
- 提供构筑导出/导入，若时间允许。
- 实现批量模拟工具。
- 输出胜率、平均战斗时长、平均剩余生命。

验收：

- 刷新页面后能恢复保存构筑。
- 命令行可运行构筑 A vs 构筑 B 的多局模拟。
- 输出可用于数值平衡。

### Phase 10：测试、调优与 MVP 封版

目标：稳定 MVP，完成第一轮数值调优。

任务：

- 补齐关键单元测试。
- 补齐 Playwright 冒烟测试。
- 批量模拟 6 个预设敌人之间的对局。
- 调整明显过强或过弱词条。
- 检查 UI 文案、视觉反馈和结算流程。

验收：

- 核心测试通过。
- 浏览器冒烟流程通过。
- 30 个词条均能在实战中触发或生效。
- 没有明显卡死、无限召唤、无限分裂、无限回血等失控情况。

## 5. 风险与应对

### 风险：词条组合爆炸

应对：

- 每个强机制设上限。
- 先保守数值。
- 使用批量模拟工具找异常胜率。

### 风险：渲染和模拟耦合

应对：

- 模拟层只输出快照和事件。
- PixiJS 不参与战斗计算。
- React 不直接修改战斗状态。

### 风险：开发范围过大

应对：

- 每个阶段都保持可运行。
- 先实现功能，再补表现。
- 导入导出、录像、服务器全部后置。

### 风险：玩家看不懂词条效果

应对：

- 战斗中显示双方词条。
- 关键效果有颜色和数字反馈。
- 结算展示双方构筑。
