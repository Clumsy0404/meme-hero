# 设计者模式与暂停调参实施计划 v0.1

## 1. 目标

为当前小球词条自动对战游戏增加一套轻量设计者模式，让设计者可以在页面内快速调整基础数值、弹道数值、炮台数值和词条数值，并通过暂停/继续/重开来直接测试效果。

第一版目标不是做完整后台，而是解决当前调平衡过于繁琐的问题：不再为了每次试数值都修改源码、跑测试、改文档、提交 git。

## 2. 核心体验

推荐第一版流程：

1. 设计者打开“设计者模式”。
2. 点击“暂停”，当前战斗画面停止推进。
3. 修改数值。
4. 点击“重新开始”，新一局立即使用修改后的数值。
5. 如果测试不满意，继续暂停、修改、重开。
6. 满意后导出当前平衡配置 JSON，后续再决定是否固化进正式源码。

第一版不做“当前局热更新”。也就是说，已经生成的小球、子弹、护盾、状态、召唤物不会在当前局中途被强行改写。这样实现更稳定，避免出现已有子弹速度、已有护盾值、已有状态持续时间等难以解释的问题。

## 3. 功能范围

### P0 必做

- 暂停/继续战斗。
- 暂停时画面保持当前状态，不继续模拟。
- 暂停时允许修改设计者数值。
- 修改后的数值在下一次“重新开始”时生效。
- 支持恢复默认数值。
- 支持导出当前设计者配置 JSON。
- 支持导入设计者配置 JSON。
- 设计者配置保存到 localStorage，刷新页面后仍可继续测试。

### P1 可做

- 自动重开开关：修改数值后自动 debounce 重开。
- 配置命名：例如“远程削弱 v1”“快节奏 v2”。
- 多套配置本地列表。
- 当前配置与默认配置的差异高亮。
- 一键复制“需要固化到代码的差异摘要”。

### 暂不做

- 当前局热更新。
- 服务端保存。
- 多人协作调参。
- 权限系统。
- 完整数值后台。

## 4. 可调数值范围

### 基础小球数值

- 最大生命
- 半径
- 移动速度
- 碰撞伤害
- 碰撞冷却
- 击退
- 减伤
- 生命回复

### 基础远程参数

- 子弹伤害
- 子弹发射间隔
- 子弹速度
- 子弹半径
- 子弹存活时间

### 炮台参数

- 炮台生命
- 炮台半径
- 炮台持续时间
- 炮台生成冷却
- 炮台子弹伤害
- 炮台子弹速度
- 炮台子弹半径
- 炮台子弹发射间隔
- 炮台子弹存活时间

### 词条数值

第一版只开放已有 numeric 字段，不新增机制编辑器。

示例：

- 生命强化：最大生命百分比
- 高速移动：移动速度百分比
- 巨型球体：半径、生命、速度修正
- 撞击强化：碰撞伤害、击退修正
- 远程核心：子弹伤害倍率
- 霰弹发射：伤害倍率、额外子弹数、散角、射速倍率
- 追踪子弹：追踪强度
- 穿透子弹：穿透次数
- 分裂子弹：分裂数量、子弹半径倍率
- 灼烧/中毒/减速/脆弱：触发概率、持续时间、伤害或效果强度
- 低血狂暴/成长/复活：触发阈值、持续时间、成长层数、复活比例等

## 5. 技术设计建议

### 设计者覆盖配置

新增一份运行时覆盖配置，暂定名称：

```ts
DesignerBalanceOverrides
```

它不替换正式内容库，而是在创建战斗或编译构筑时覆盖默认值。

推荐覆盖层级：

1. 默认源码配置
2. 设计者 localStorage 配置
3. 当前页面临时编辑值

最终战斗使用合并后的配置。

### 应用时机

第一版只在以下时机应用覆盖配置：

- 页面初始化读取配置
- 点击“重新开始”创建新战斗
- 导入配置后点击“应用并重开”

暂停时修改配置不直接改当前战斗世界。

### 暂停机制

战斗运行状态建议增加：

```ts
type BattleRunState = "running" | "paused" | "ended";
```

当状态为 `paused` 时：

- 不调用 `stepBattle`
- 不推进战斗时间
- 不生成新事件
- Pixi 画面保留最后一次 snapshot
- UI 可以继续编辑构筑和设计者参数

当点击继续：

- 从当前 world 继续模拟

当点击重新开始：

- 使用当前构筑 + 当前设计者覆盖配置创建新 world
- 状态回到 running

## 6. UI 规划

建议在现有界面增加一个设计者面板，而不是做独立页面。

### 顶部控制

- 暂停/继续按钮
- 重新开始按钮
- 设计者模式开关

### 设计者面板

可按标签页分组：

- 基础
- 远程
- 炮台
- 词条
- 配置

控件建议：

- 数值使用输入框 + 小步进按钮
- 百分比使用输入框或滑条
- 布尔项使用开关
- 恢复默认放在每个分组底部
- 全部恢复默认放在配置页

## 7. 实施阶段

### 阶段 1：暂停/继续

目标：先让测试时可以停住画面。

任务：

- 增加 battle run state。
- UI 增加暂停/继续按钮。
- 暂停时停止 stepBattle。
- 继续时从当前状态恢复。

验收：

- 点击暂停后战斗时间不再变化。
- 小球、子弹、炮台位置不再变化。
- 点击继续后战斗恢复。
- 点击重新开始仍可正常开新局。

### 阶段 2：设计者覆盖配置骨架

目标：建立可覆盖数值的数据结构。

任务：

- 定义 DesignerBalanceOverrides 类型。
- 实现默认配置到覆盖配置的合并函数。
- 将基础小球数值、基础弹道数值、炮台数值接入覆盖。
- localStorage 读写。

验收：

- 修改覆盖配置后，重新开始可使用新数值。
- 刷新页面后覆盖配置仍存在。
- 恢复默认后使用源码默认值。

### 阶段 3：设计者 UI 第一版

目标：能在页面上直接调核心数值。

任务：

- 增加设计者模式开关。
- 增加基础/远程/炮台三个分组。
- 每个字段显示当前值、默认值和输入控件。
- 修改后提示“下次重新开始生效”。

验收：

- 不改代码即可调生命、速度、碰撞伤害、子弹伤害、子弹速度、炮台子弹伤害等。
- 点击重新开始后立即用新数值战斗。
- 面板最终属性显示与战斗实际值一致。

### 阶段 4：词条数值编辑

目标：能调每个词条的 numeric 参数。

任务：

- 遍历词条定义，生成可编辑字段。
- 支持 statModifiers、collision、projectile、summon、status、rule 分类字段。
- 支持每个词条单独恢复默认。
- 支持全部词条恢复默认。

验收：

- 可修改霰弹伤害倍率、远程核心伤害倍率、状态触发概率等。
- 修改后重新开始生效。
- 非数字字段暂不开放或只读显示。

### 阶段 5：导入/导出配置

目标：方便保存和回滚平衡方案。

任务：

- 导出当前覆盖配置 JSON。
- 导入覆盖配置 JSON。
- 校验版本号和字段合法性。
- 导入后可选择“仅保存”或“保存并重开”。

验收：

- 导出的 JSON 可复制保存。
- 导入同一 JSON 后能恢复相同数值。
- 非法 JSON 给出错误提示，不破坏当前配置。

## 8. 风险与处理

- 风险：调参字段太多导致 UI 混乱。
  - 处理：第一版只开放核心字段，词条数值编辑放到阶段 4。

- 风险：当前局热更新导致状态不一致。
  - 处理：第一版只做“重新开始后生效”。

- 风险：覆盖配置与源码默认配置偏离太久。
  - 处理：导出配置时显示差异，定期挑选稳定配置固化到源码。

- 风险：文档、源码、设计者配置三套数值不同步。
  - 处理：把设计者配置视为实验层；只有确认后才同步源码和文档。

## 9. 推荐下一步

建议下一阶段先做“阶段 1 + 阶段 2”：

- 先加暂停/继续。
- 再接入基础小球、基础远程、炮台三组运行时覆盖。

这样最小可用版本就能满足“暂停后调数值，重开后立刻测试”的需求。
